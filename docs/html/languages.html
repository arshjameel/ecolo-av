Our ROS nodes are Python, and the firmware and hardware drivers are Rust. The C++ we inherited is now Rust (Ben, 10 and 15 Oct): none of our ROS code is C++. Only today's ESP32 firmware still is, and the hardware lead's wheel-sensor Arduino (Ben, 23 Oct). ROS 2 lets each program pick its own language, because programs only meet through messages.

How languages fit into ROS 2

  • Every node is its own program, so a Python node and a C++ node talk without knowing it.
  • Each .msg file is generated into Python, C++ and Rust, so every language sees the same types.
  • The client libraries all wrap one C core, rcl, so they behave the same.

Is C++ too risky?

Memory bugs and crashes are a fair worry with C++. In this stack:

  • The C++ we run is almost all stock packages that thousands of robots use. We wrote none of it.
  • Our own code is Python and Rust, and both are memory-safe. The inherited C++ is now Rust; only today's ESP32 firmware is still C++, until its Rust version replaces it (and the hardware lead's Arduino).
  • Each node is a separate process. A crash takes down one node, not the whole system.
  • Safety never rests on one program: ego's timeout and the spine's watchdog stop the car if a node dies.

What if everything were Rust?

You'd get You'd give up
Memory safety and speed in every node Official support: rclpy and rclcpp are official; rclrs is a community project
One language from the firmware up Examples: most ROS answers and tutorials are Python or C++
Cargo, and its tooling Simple builds: colcon needs a cargo plugin, and builds get slower
Nothing in Nav2 or robot_localization: they stay C++, and we'd still only configure them
Launch files: they stay Python
An easy hand-over: the 2027-28 team has to know Rust

Where Rust stands in October 2026:

  • Message crates ship with Jazzy. Our Pixi install already has them, for example share/sensor_msgs/rust/.
  • rclrs, the library for writing nodes, comes from crates.io and is still 0.x.
  • It works here. The IMU driver (aav_imu_yahboom), the radar clustering, the CAN bridge (aav_spine_bridge) and the HUD are rclrs nodes, built by colcon. A first example, examples/rust-listener, showed it in October; it was removed on 26 Oct, once these real nodes showed the same.
