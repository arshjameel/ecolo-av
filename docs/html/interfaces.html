/system/source aav_interfaces/msg/DataSource gazebo_adapter, turtlesim_adapter, spine_bridge, legacy_uart_bridge, mock_imu, mock_gps, mock_battery, mock_camera, mock_radar, mock_lidar, replay_source, carla_adapter, camera_stream_front_left, camera_stream_front_right hud, map, actuator_test, point_driver, point_cli, sensor_mux, output_mux, debug_hud, hw_panel turtle, sim, car, replay, bench Latched (reliable, transient local, depth 1). Where the data comes from - REAL, SIM, BENCH or REPLAY - per sensor, one list per announcer. Gazebo and turtlesim announce SIM; spine_bridge REAL on the car, BENCH on the bench and SIM in Gazebo's spine profile (its source parameter; gazebo_adapter then announces only the sensors), with each bench stand-in - with role:=sensors (today's wiring, the Orin's CAN bus with only the wheel sensors) only odometry and wheels, never an actuator; legacy_uart_bridge REAL; replay.launch.py REPLAY; each camera_stream_ its camera (camera_front_left...) as its source parameter says, REAL on the car. /system/sensor_mux/state aav_interfaces/msg/SourceCheck sensor_mux output_mux turtle, sim, car, replay, bench The sensor mux's verdict, 2 Hz (aav_io_mux sensor_mux, source:=real, sim, bench or replay) - ok when each sensor topic it watches (provenance.SENSORS - the IMU, GPS, cameras, radar, lidar, wheels, odometry, battery) has at most one publisher, that publisher's source as /system/source says (an unannounced one counts as REAL - the car's stock drivers can't announce), and every announcement equals source. An announcement of another source is a problem at once; a graph finding (two publishers, an unannounced one in a simulator) is a doubt until it has lasted 5 s (provenance.Hold), as a node can be seen before its announcement or its name arrive. Silent for its first 2 s, while discovery settles. It relays no data - it checks where the data comes from - so the heavy topics (pictures, point clouds) cost nothing extra.

/diagnostics diagnostic_msgs/msg/DiagnosticArray twist_mux, ekf_local, ekf_global, sensor_watchdog, camera_stream_front_left, camera_stream_front_right language_drive - ROS's diagnostics. sensor_watchdog reports each input it watches once a second (OK, WARN, ERROR when it stops the car); for the wheels, also the gaps to the IMU (speed_gap, turn_gap, worst_speed_gap, worst_turn_gap), to tune the cross check on the car. twist_mux reports each lock once a second ("lock locks.estop" locked or free) - the only place a node started after an e-stop can learn it, since /safety/estop is sent a few times and its senders go away. language_drive refuses to move while it says locked, or while it is silent. camera_stream_ reports its stream once a second (status name camera_stream - front_left; ERROR with no pictures, WARN under half the frame rate) - decoder (the one auto picked - gst-mac on a Mac), fps_in, fps_out, dropped, decoder_starts, work_ms, detect_ms, delay_s, and with time_code the measured delays (arrival_ and detection__ms - median, p95, max). pixi run check ignores the topic.
