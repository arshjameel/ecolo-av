New to the team? Start here. In about an hour you'll have ROS on your laptop, drive a turtle that steers like the car, see every node and topic in rqt_graph, drive the simulated car in Ravensim, and watch our stack plan a path through a costmap. Each step says what you should see.

What you need
A laptop a Mac (macOS 14 or newer) or a 64-bit Linux laptop
Disk space about 30 GB free: the environment (.pixi) 5.5 GB, the build (build/, a compile folder for each Rust package) 9.4 GB, and pixi run test, which also builds the firmware for each board (a Mac, 20 Nov: 20 GB ran out)
Time about an hour, most of it the first download
Admin rights not needed
The code a GitHub account with an SSH key, and your own fork of AAV-2025-2026/ecolo-av (public)

1. Install everything (once, about 20 minutes)

xcode-select --install                        # Mac only: Apple's git and compiler
curl -fsSL https://pixi.sh/install.sh | sh    # Pixi; then open a new terminal
git clone git@github.com:<you>/ecolo-av.git ~/ecolo-av   # your fork
cd ~/ecolo-av
git remote add upstream https://github.com/AAV-2025-2026/ecolo-av.git   # the team's repo
pixi install                                  # ROS 2 Jazzy, about 7 GB
pixi run build                                # our packages, about 20 s
pixi run test                                 # every test

Fork first: on GitHub, open AAV-2025-2026/ecolo-av and click Fork. How changes get in: CONTRIBUTING.md.

You should see at the end of the tests: 0 errors, 0 failures. Then your laptop is set up. If not, see When something doesn't work.

What did that install?

Pixi put ROS 2 Jazzy, Python, Rust and the compilers inside the .pixi folder of the repo. Nothing else on your laptop changed, except one line in your shell settings so that the pixi command is found.

2. Drive the turtle (10 minutes)

Terminal 1 Terminal 2
pixi run turtle pixi run keyboard --local

You should see: a blue window with a turtle. Click into terminal 2 and hold i: the turtle drives forward. u and o curve left and right. Let go, and it stops within about half a second.

The turtle steers like the car: it can't turn on the spot. Your key press took the same path a real drive takes:

# Step Topic
1 The keyboard proposes a speed and a turn rate /drivers/keyboard/cmd_vel
2 twist_mux picks the highest-priority driver /control/cmd_vel
3 ego turns it into a speed and a steering angle the car can do /ego/actuator_cmd
4 turtlesim_adapter moves the turtle /turtle1/cmd_vel

3. See the graph (5 minutes)

Leave the turtle running. In terminal 3:

pixi run graph      # rqt_graph

You should see boxes (nodes) joined by arrows (topics). To make it readable:

  • pick Nodes/Topics (active) in the drop-down at the top left;
  • tick Hide: Debug and Hide: tf;
  • click the refresh button after you start or stop something.

Follow the chain from section 2: teleop_twist_keyboard → /drivers/keyboard/cmd_vel → twist_mux → /control/cmd_vel → ego → /ego/actuator_cmd → output_mux → /control/turtle/actuator_cmd → turtlesim_adapter.

Then check the graph against the team's contract:

pixi run check turtle

You should see 0 failed at the end. The contract is docs/interfaces.yaml: every topic, its type, and who publishes and reads it.

4. Ravensim: the simulated car (15 minutes)

Stop the turtle first (Ctrl-C in each terminal).

pixi run sim                        # the same on Linux and on a Mac
tools/software_gl.sh pixi run sim   # a computer with no GPU (slower than real time)

You should see:

  • RViz: the car model, the map, and the costmaps around the car.

Ravensim is our own simulator, in Rust (its page). Watch it in RViz, in Lichtblick (Foxglove), or in the developer window: pixi run ravensim starts the sim and the window together.

Drive it with pixi run keyboard --sim in another terminal. Then run pixi run check sim: it should say 0 failed.

5. A goal through a costmap (10 minutes)

In RViz:

  1. Click 2D Goal Pose in the toolbar.
  2. Click on the map about 8 m ahead of the car, and drag to set the direction.

You should see a planned path appear, and the car drive along it and stop at the goal. Any keyboard or joystick input overrides the navigator at once.

Our stack (stack:=ours) does it, all in Rust:

Part Package Job
navigator aav_navigator takes the goal, replans, recovers
planner aav_planner the path, through the costmap
path follower aav_mppi_lag follows the path
costmap aav_costmap the grids it plans through: local (20 m × 20 m around the car) and global (the whole map)

For walls to plan around, start Ravensim with the test lot instead: pixi run sim world:=test_lot. Costmaps explains how to draw your own.

The same goal from a terminal

The navigator serves Nav2's action name and message, so goal senders stay the same: pixi run tools/ros.sh ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{pose: {header: {frame_id: map}, pose: {position: {x: 8.0, y: 0.0}, orientation: {w: 1.0}}}}"

When something doesn't work

Symptom Try
pixi: command not found open a new terminal, or run ~/.pixi/bin/pixi
"Not built yet" pixi run build
A test fails run pixi run test again. If it still fails, paste the last 20 lines into the team chat or into Claude
The turtle doesn't move click into the keyboard terminal and hold the key; see when nothing moves
macOS asks whether python3 or rviz2 may accept connections click Allow
Two laptops see each other's robots give each its own ROS_DOMAIN_ID, 0–101 (safe on Linux; Fast DDS breaks above 232)
