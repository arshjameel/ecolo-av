Ben, 16 Nov: "lets test and score everything and fingure out the best options and maybe even the best hybrid options. Check the internet for other options too", then "What is our final configuration ... score them individually and then score them together".

Every option was scored in our simulator with everything else at stack:=ours, reversing on, on the same tours. The rule (the league): a challenger wins by a margin on 3 or more runs, with no column worse.

Final configuration

No champion changed. Today's stack:=ours stays the best whole car. One challenger is close: NDT into the global EKF (pose:=ndt_ekf). It wins most columns, but not all.

The survey: open source we haven't tried

Licences read from each project's GitHub record on 16 Nov. Our rule: learn from it, write it ourselves in Rust or Python; none installed.

Follower

Option Licence, language What it does better Fit
Smooth MPPI / KMPPI (pytorch_mppi) MIT, Python samples the steering's change (or a few knots), so the commands come out smooth port into mppi_lag: our sway
Autoware's MPC lateral controller (autoware_universe) Apache-2.0, C++ steering lag and dead time in the model, a steering-rate cost, reverse port into mpc_lag_rs: what it lacks above
Vector Pursuit (vector_pursuit_controller) Apache-2.0, C++ pure pursuit that also aims the heading; reverses a small yardstick beside RPP

Path

Option Licence, language What it does better Fit
Piecewise-jerk path (Apollo's EM planner, apollo) Apache-2.0, C++ a QP along the lane: keeps the lane, bends round a parked thing under a jerk limit port into lane.rs with Clarabel: smooth corners and passes
Autoware static obstacle avoidance (behavior_path_planner) Apache-2.0, C++ the pass's length from the speed and a lateral-jerk limit (0.3-2 m/s³) port the formula into pass.rs
Autoware path optimizer (elastic band + MPT) Apache-2.0, C++ the path made drivable (bicycle model) before the follower sees it idea for plan_smoothing

Costmap and ground

Option Licence, language What it does better Fit
Patchwork++ (patchwork-plusplus) BSD-2-Clause, C++ finds the ground ring by ring, so a 0.3 m kerb stands out port: the kerbs we miss (TODO 119)
grid_map (grid_map) BSD-3-Clause, C++ many layers on one grid idea for our costmap's layers
nvblox (nvblox) Apache-2.0, C++/CUDA a distance field on the GPU (the Orin has one) a yardstick only: a big stack

Lanes and routing

Option Licence, language What it does better Fit
Lanelet2's routing graph (Lanelet2) BSD-3-Clause, C++ lane changes as edges in the route add to lane.rs's Dijkstra (we read Lanelet2 in Rust)
CommonRoad route planner (commonroad-route-planner) BSD-3-Clause, Python the reference path and where to change lane idea for lane.rs
Maliput (a Rust API over C++) not checked OpenDRIVE roads with routing only if we take OpenDRIVE maps

Things (what moves)

Option Licence, language What it does better Fit
Fast-Poly / Poly-MOT (FastPoly) MIT, Python a motion model per kind (bicycle for a car, constant speed for a person) port into aav_things (one constant-velocity filter today)
OC-SORT (OC_SORT) MIT, Python a thing lost then found re-fits its speed from its last sightings port into our tracker
MapMOS (MapMOS) MIT, Python (a network) moving points against the map idea for things_background, later

Where the car is (lidar)

Option Licence, language What it does better Fit
Kinematic-ICP (kinematic-icp) MIT, C++ KISS-ICP with the wheels and a car that can't slide sideways the next kiss_ekf challenger, ported
small_gicp (small_gicp) MIT, C++ fast GICP on many cores a yardstick for NDT
GenZ-ICP (genz-icp) MIT, C++ mixes plane and point matching by the scene: long straight roads idea for NDT on University Drive
