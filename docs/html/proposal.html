A snapshot from 15 October 2026. What's true now: Status and The plan.

Written 15 October 2026, for the team (Ben: "a file called proposal that lists everything we have talked about that we think we can get working"). This is the draft for the written proposal: every part of the car, what's built, what's left, and how sure we are. Details live in the pages linked from each row.

The short version - The goal: the 2025-26 car drives itself from one GPS point to another, safely, with a person watching on two screens. - Already built and tested in simulation: the whole software stack on ROS 2 Jazzy. Sensors, position (EKFs), Nav2, ego, the safety path, perception, two screens, plain-English driving. Linux and Mac. - Not yet done: almost everything on the real car. Measuring it, the sensors it's missing for closed-loop control, the Jetson upgrade, and real drives. - Status words: ✅ done and tested · 🧪 built, tested only in simulation or on the bench · 🔧 to build, confident · 🎯 stretch goal.

The missing sensors for closed loop

Actuator We command it We need to read back Plan
Steering yes the real wheel angle the Jrk motor controller already reports its position (the 2024-25 firmware read it); wire it into /vehicle/steering
Throttle yes wheel speed: is it moving as asked? the wheel encoder exists (one wheel); check it's reliable. Or a Hall sensor on each front wheel (the KEFC plan, the hardware lead to decide): CAN v0.2.0 and spine_bridge already read them into /vehicle/wheels and /vehicle/odom (bench, 15 Oct)
Brake yes brake position or pressure a position sensor on the brake actuator: to choose after the audit
E-stop the red button its state the spine reads it; never in its path

The topics for all four already exist (/vehicle/steering, /throttle, /brake, /wheels); the simulator fills them today, and the bench fills /wheels from the CAN wheel frames.
