A snapshot from 16 October 2026. The audits ran on 16 and 21 Oct: 16 Oct, 21 Oct. What's true now: Status.

The first time the 2026-27 team logs in to the car's computers. The goal: know what is there, and save a copy, without changing anything. This page is steps 2 and 3 of Work ("Backups", "Inventory the car"), and it covers the checklist at the end of Car photos.

Read-only first

Look, copy and photograph. Don't install, upgrade, reflash, restart services, change the network, or drive. The "don't" list is at the end of this page.

The plan for the whole day (audit, network, our stack on the car): Friday 16 Oct. Every question to answer: Friday's questions.

After the backups: our stack, from a USB stick

If the team agrees, once a machine is backed up: From a USB stick puts our Jazzy in ~/aav-jazzy with no internet and no sudo, and leaves Humble alone. Its car_listen.sh is read-only: it says which devices our drivers could open.

Remember: the car speaks Humble, not our names

Use ros2 topic list; don't assume our names

The car runs the 2025-26 software on ROS 2 Humble, with its own topic names (such as /gps/fix, /cmd_vel). Our names, like /sensors/gps/fix, only exist in our Jazzy code. On the car, list what is really there with ros2 topic list -t, and write down the names you see. Humble and Jazzy don't mix: don't run our stack against it.

Step 2: find each machine

Plug the laptop into a spare switch port (or join the car's WiFi). Then, on a Mac or Linux:

ifconfig | grep "inet "          # your own address: the car's network is probably 192.168.1.x
arp -a                           # every machine your laptop has heard from
nmap -sn 192.168.1.0/24          # if nmap is installed: every machine that answers

Also open the router's page (step 4, "The router") and copy its client list: it names each machine with its address.

aav-desktop is dual-homed (.195 = .196)

.195 and .196 have byte-for-byte identical SSH host keys (RSA and ed25519) and consecutive MACs (…0d:49 / …0d:4c): one physical machine with two Ethernet ports on the switch, not two machines. Untangle this — two interfaces on one subnet can make DDS bind oddly.

Step 3: back up first

Before any check, copy each Linux machine to the encrypted drive. Check the sizes first:

ssh <user>@<ip> 'df -h /; sudo du -sh /home /etc /opt 2>/dev/null'
Way When Size (guess) Command (run on the laptop)
rsync the home folder every machine, Friday 1-20 GB a Pi; more on the Orin (models, bags) rsync -a --exclude .cache <user>@<ip>:/home/<user>/ ~/aav-backup/<machine>/home/
tar /etc every machine, Friday under 50 MB ssh <user>@<ip> 'sudo tar czf /tmp/etc.tgz /etc', then scp <user>@<ip>:/tmp/etc.tgz ~/aav-backup/<machine>/, then ssh <user>@<ip> 'sudo rm /tmp/etc.tgz'
SD card image a Pi, only if the team agrees to shut it down the card's size (16-128 GB) before gzip on a Mac: below the table
Full Orin image not Friday: needs an x86 Ubuntu PC and recovery mode the whole eMMC or SSD l4t_backup_restore.sh (Platforms)

The SD card image, on a Mac (the card in the reader, N from diskutil list):

diskutil list                                   # find the card: /dev/diskN, its size
diskutil unmountDisk /dev/diskN
sudo dd if=/dev/rdiskN bs=4m | gzip > ~/aav-backup/<machine>.img.gz
  • The /tmp/etc.tgz file is the only thing written on the car on Friday, and it is deleted straight after.
  • With dd, if= is the card you read from. Swap if and of and you erase it. Have a second person read the command before you press Enter.
  • The backups hold secrets (WiFi passwords in /etc/NetworkManager, SSH keys, password hashes). Keep them on the encrypted drive. Never in git, never in a shared folder.
  • The Orin holds the only copies of the 2025-26 stop-sign detector, camera_decode and the OSRM map data (Older code). Back it up first.

Step 4: the read-only checks

The block for every Linux machine

The logins, from the Keychain (20 Oct)

Each line of ~/aav-audit/hosts.txt may name a Keychain entry as its third column (JETSON aavjetson@192.168.1.140 aav-jetson). The survey then gets that machine's password from the Mac's Keychain itself (tools/keychain_askpass.sh): nobody copies passwords, and none is ever written to a file. Add an entry with security add-generic-password -s aav-jetson -a aavjetson -w (it asks).

Now a script: pixi run survey

Friday 16 Oct: the to-do list part 2: tools/machine_survey.sh does all of the block below and more (boot scripts, who holds each device, camera and power errors, code and weights found only here), on every machine in ~/aav-audit/hosts.txt. The block below stays as the by-hand version.

Save this as audit.sh on your laptop, then run it from the laptop:

ssh <user>@<ip> 'bash -s' < audit.sh > ~/aav-audit/<switch label>.txt 2>&1

Nothing is saved on the car. The output stays on your laptop.

# audit.sh: read-only. Prints what a machine is and what it runs.
echo "== who";        hostname; whoami; date; uptime
echo "== os";         cat /etc/os-release; uname -a
echo "== disk";       df -h
echo "== memory";     free -h
echo "== network";    ip -br addr; ip route
echo "== running";    systemctl list-units --type=service --state=running --no-pager
echo "== enabled";    systemctl list-unit-files --state=enabled --no-pager
echo "== added";      ls -la /etc/systemd/system
echo "== cron";       crontab -l 2>&1; ls /etc/cron.d
echo "== devices";    ls -l /dev/tty* /dev/serial* /dev/video* /dev/can* /dev/i2c* 2>/dev/null | grep -v "tty[0-9]"
echo "== by-id";      ls -l /dev/serial/by-id 2>/dev/null
echo "== usb";        lsusb
echo "== ros env";    printenv | grep -i ros; grep -n "ROS\|source" ~/.bashrc
echo "== ros";        ls /opt/ros 2>/dev/null
echo "== workspaces"; ls -d ~/*/src ~/*/install 2>/dev/null
echo "== docker";     docker ps -a 2>&1
echo "== busiest";    ps aux --sort=-%cpu | head -25
echo "== udp ports";  ss -uapn 2>/dev/null | head -30
echo "== ros graph"
for d in /opt/ros/*/setup.bash; do source "$d"; done
export ROS_DOMAIN_ID=$(grep -o 'ROS_DOMAIN_ID=[0-9]*' ~/.bashrc | tail -1 | cut -d= -f2)
echo "domain: ${ROS_DOMAIN_ID:-0 (not set)}"
timeout 30 ros2 node list --no-daemon --spin-time 5
timeout 30 ros2 topic list -t --no-daemon --spin-time 5
  • An ssh session doesn't read .bashrc, so the block reads the domain from it. The 2025-26 team used 10 on the dashboard and 0 on the UI. If the graph is empty, try both: export ROS_DOMAIN_ID=10.
  • --no-daemon keeps ros2 from starting its background daemon on the car.
  • Before you share an output file, read it. printenv, .bashrc and crontab can hold tokens or passwords. Cut them out.

No secrets in the write-up

Before you commit, search the file: grep -n -i -E "pass|psk|token|secret|key|ntrip" docs/history/audit-2026-10-16-car.md. For each hit, write only where the secret is and what kind it is (as Older code does). The raw outputs in ~/aav-audit/ stay off git.

Commit the page on its own branch, then pixi run docs if you link it from a page.

Don't

Don't Why
apt upgrade, apt install, pip install it changes what the 2025-26 software runs on
Reflash, or move the Orin to JetPack 7.2 not before a full image (Platforms)
Change the network: IPs, WiFi, the router, netplan the machines find each other by fixed addresses
Start, stop or restart services, or reboot something may be driving the car
Drive, or start our stack (pixi run car) Humble and Jazzy don't mix; nothing is tested on the car
Configure the GPS receiver, the radar or the lidar their settings are part of what we're recording
Open the ESP32's update page, or flash any board no password, and no way back without a backup
Copy passwords, tokens, keys or the WiFi password into notes, chat, photos or git they must be changed, not spread (Q34)
