## The idea in one line

Each idea lives in `ros/`, is built and tested with everything else, runs **beside**
today's default (chosen at launch), and is **scored on the same routes**. It becomes the
default only once it wins.

## The shape: a stand-in for Nav2's FollowPath

The review found the blocker in the first draft: a new twist_mux slot would skip
collision_monitor, which guards only Nav2's chain. So `aav_track` slots **into** Nav2
instead, where Nav2's own controller sits:

```
goal ──► bt_navigator ──► planner_server (Smac Hybrid-A*), replans every 1 s
                │
                │ FollowPath action ("follow_path")
                ▼
   tracker:=none (default)        tracker:=stanley | lqr | mpc | pure_pursuit
   controller_server              aav_track serves "follow_path";
   (MPPI or RPP)                  controller_server's own is renamed out of the way
                │                              │
                └──────────► cmd_vel_nav ◄─────┘
                                  │
                velocity_smoother → collision_monitor → /drivers/nav/cmd_vel (twist_mux 20)
```

- **Nothing in the safety path changes:** the same smoother, collision_monitor, twist_mux
  slot (20), locks and e-stops. No new topic in twist_mux.
- **The same planner, the same 1 s replanning, the same goals:** `controller-compare` keeps
  sending `NavigateToPose`; only the follower differs.
- **controller_server keeps running** (its costmaps and the trees' clear-costmap calls still
  work); with a tracker on, its action is remapped to `follow_path_unused`.

## Fair comparison: the rules

| Rule | Why (the review) |
|---|---|
| The trackers' **control is our pure pursuit**, in the same node. RPP and MPPI are a separate "whole stack" table | RPP and MPPI set their own speed; comparing steering laws needs the same speed policy |
| One speed policy for every tracker: cruise at RPP's `desired_linear_vel`, slow for curvature (`line.turn_speed_limit`), stop by `approach.planned_deceleration` | off-path error grows with speed |
| Goal reached by Nav2's own tolerances, read from `nav2.yaml` (xy 1.0 m, yaw 0.75 rad); a progress check as Nav2's | the same "done" for all |
| Track on `/localization/odom/local`; each new path moved from `map` into `odom` by TF | the global pose jumps with GPS; Nav2's controllers use `odom` |
| `reversing:=false` (as `controller-compare` already forces) | the trackers drive forwards only |
| Each follower **3 runs** per tour; mean and spread | MPPI is random; one run can't name a winner |
| Each tracker's **loop time and missed 20 Hz ticks** recorded | a slow MPC mustn't look like bad maths |

## The tracker interface

A small class per tracker, no ROS (CLAUDE.md: keep the maths out of ROS), its own tests:

```python
class Tracker:
    def reset(self, path):                  # a new path, in odom
    def step(self, state, dt) -> Command:   # Command(steer, speed_cap=None, debug={})
# state: pose (x, y, yaw) at base_link, speed v, yaw rate, the last steering command
# limits: max steering and steering rate from vehicle.yaml (aav_description.vehicle)
```

| Tracker | Built from | Notes |
|---|---|---|
| pure pursuit | `aav_drive_to_point` `line.pursuit_curvature`, `to_car`, `wrap` | new: the carrot search along a `nav_msgs/Path` |
| Stanley | heading error + atan(k·e / v), at the **front axle** (base_link + wheelbase) | soft speed term near 0 |
| LQR | `aav_ego` `VehicleModel.lateral(v)`, state `[e_y, e_θ, δ]`, `scipy.linalg.solve_continuous_are`; gains tabled by speed | + feed-forward `atan(L·κ_path)` (it's linearised about straight); a lowest speed for the schedule |
| MPC | the same model, discrete at 20 Hz (`lateral_discrete`), horizon ~1.5 s, steering and rate limits as bounds, warm start, scipy | may set `speed_cap` |

Commands go out as TwistStamped (v, ω = v·tan δ / L: `aav_ego.ackermann.curvature`). At
v ≈ 0, ω carries no steering, so the trackers don't steer at a standstill.

## Localization trial: AMCL

| Setting | Value | Why |
|---|---|---|
| World | `test_lot` with `nav:=true lidar:=true` only | the only world with a real map; `/sensors/lidar/scan` exists only there |
| `tf_broadcast` | **false** | stock AMCL publishes `map → odom`, which would fight `ekf_global` |
| Pose out | `amcl_pose` → `/localization/amcl/pose` (in `interfaces.yaml` first) | our naming rule |
| Start | the sim's start pose (`set_initial_pose`) | |
| Lifecycle | its own lifecycle manager | Nav2's lists only its servers |
| Scored by | `controller-compare --amcl` records it beside the EKF; `drive_metrics.belief_errors` | no new tool |

AMCL publishes only after moving (`update_min_d`), so parked scores come from few samples:
said so in the results. Gazebo's map is perfect and its GPS noise simple, so **a localizer
feeds the EKF only after it also wins on a bag from the real lot.** On the car,
`slam_toolbox`'s map needs aligning to the GPS `map` frame first.

| T2 | MPC in Python first, or straight to Rust? | Python (scipy) for the trial; Rust only if it wins |

| T4 | Does remapping controller_server's action work in Jazzy? | **Yes**: `rcl_action_server_init` resolves the action name with `rcl_node_resolve_name(..., only_expand=false)`, so a node's remappings apply as to topics (vendor `rcl_action/action_server.c`). The launch passes `('follow_path', 'follow_path_unused')` |
| T5 | `cmd_vel_nav`: Twist or TwistStamped? | **TwistStamped**: nav2.yaml sets `enable_stamped_cmd_vel: true` on controller_server and velocity_smoother; aav_track's `stamped` comes from it. `/cmd_vel_nav` goes in the contract as Nav2's own name |
| T6 | Which steering-rate limit do the trackers use? | **The lower of vehicle.yaml's `steer_rate` (0.8) and ego.yaml's `max_steering_rate` (0.6)**: ego clamps the command to its own anyway |
| T7 | How does the debug come out? | **`/drivers/nav/track/status`, a `diagnostic_msgs/DiagnosticStatus` every tick**: loop_ms, loop_ms_max, missed_ticks, cross track, steering. Not `/diagnostics`: check_graph ignores that, and controller-compare reads it per leg |
| T8 | A tracker with `reversing:=true`? | **Refused at launch** with "add reversing:=false": the planner's Reeds-Shepp paths would be followed forwards. `sim.launch.py` reverses by default, so trials there need `reversing:=false` (controller-compare passes it) |
| T9 | The bend's speed limit | **`lateral_accel` 1.0 m/s²** (config/track.yaml): it binds only above the car's 1 m/s (at 3 m/s on the tightest turn, about 1.7 m/s). The speed-up rate is the velocity smoother's `max_accel` (1.0) |
| T10 | MPC's model | **`VehicleModel.lateral(v)` discretised with the bend as a second input** (`scipy.signal.cont2discrete`), not `lateral_discrete`: that one returns the loop closed with pure pursuit's gains. SLSQP only when the unconstrained answer breaks a bound |
| T11 | `controller-compare --trackers` alone | **Runs only the trackers**; add `--controllers rpp mppi` for the whole-stack table. Neither flag: both of Nav2's, as before |
| T12 | AMCL's start pose | **`amcl_x/amcl_y/amcl_yaw` on navigation.launch.py**; sim.launch.py passes (0, start_y, start_yaw), the car's true start in the map frame |
